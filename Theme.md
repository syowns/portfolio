<h3 id="purpose">Purpose</h3>

<p>This guide explains how to switch between Jekyll themes (such as <strong>Minima</strong>, <strong>TeXt</strong>, <strong>So Simple</strong>, and others) in your site, while supporting custom layouts and behaviors. The approach allows students or contributors to select a theme and still benefit from local overrides and customizations.</p>

<h2 id="theme-switching-logic">Theme Switching Logic</h2>

<h3 id="directory-structure">Directory Structure</h3>

<ul>
  <li>_themes/
    <ul>
      <li>minima/
        <ul>
          <li>_config.yml</li>
          <li>Gemfile</li>
          <li>opencs.html</li>
          <li>_layouts/
            <ul>
              <li>post.html</li>
              <li>page.html</li>
            </ul>
          </li>
        </ul>
      </li>
      <li>text/
        <ul>
          <li>_config.yml</li>
          <li>Gemfile</li>
          <li>opencs.html</li>
          <li>_layouts/
            <ul>
              <li>post.html</li>
              <li>page.html</li>
            </ul>
          </li>
        </ul>
      </li>
      <li>…</li>
    </ul>
  </li>
</ul>

<h3 id="layout-overrides">Layout Overrides</h3>

<ul>
  <li>For <strong>Minima</strong>, custom behaviors are implemented by overriding <code class="language-plaintext highlighter-rouge">post.html</code> and <code class="language-plaintext highlighter-rouge">page.html</code> in your project’s <code class="language-plaintext highlighter-rouge">_layouts/</code> directory. These custom layouts <strong>terminate with</strong> <code class="language-plaintext highlighter-rouge">opencs.html</code>, a local layout that you control for further overrides.</li>
  <li>For other themes, the theme-specific <code class="language-plaintext highlighter-rouge">post.html</code> and <code class="language-plaintext highlighter-rouge">page.html</code> in <code class="language-plaintext highlighter-rouge">_themes/&lt;theme&gt;/_layouts/</code> use front matter to load the theme’s default or base layout as their terminating layout (e.g., <code class="language-plaintext highlighter-rouge">layout: default</code> or <code class="language-plaintext highlighter-rouge">layout: base</code>).</li>
</ul>

<p><strong>This means:</strong></p>

<ul>
  <li>You can always override or extend layouts by editing your themes <code class="language-plaintext highlighter-rouge">opencs.html</code>.</li>
  <li>For themes other than Minima, the default theme layouts is being used unless you add overrides.  In minima, you can see we brought the base.html local as well as many _sass files.</li>
</ul>

<hr />

<h2 id="how-to-switch-themes">How to Switch Themes</h2>

<h3 id="using-the-makefile">Using the Makefile</h3>

<p>The Makefile includes targets to copy the appropriate config, Gemfile, and layouts from <code class="language-plaintext highlighter-rouge">_themes/&lt;theme&gt;/</code> into the project root and <code class="language-plaintext highlighter-rouge">_layouts/</code> directory:</p>

<div class="language-bash highlighter-rouge"><div class="highlight"><pre class="highlight"><code>make use-minima
make use-text
make use-cayman
make use-so-simple
</code></pre></div></div>

<ul>
  <li>All theme-specific configuration and override files are stored in the <code class="language-plaintext highlighter-rouge">_themes/</code> directory (not built by Jekyll).</li>
  <li>Each theme has its own set of files.  Read the Makefile to see the copy rules.</li>
</ul>

<h3 id="how-layouts-are-resolved">How Layouts Are Resolved</h3>

<ul>
  <li>Jekyll will first look for layouts in your project’s _layouts/ directory.</li>
  <li>If not found, it will use the layout from the remote theme.</li>
  <li>This allows you to override any layout by placing a file of the same name locally.</li>
</ul>

<h2 id="styling-preferences-tutorial-how-it-works">Styling Preferences Tutorial (How It Works)</h2>

<p>Many modern Jekyll-based sites allow visitors to adjust small styling preferences—such as font size, font family, text color, background color, and content width—without changing the underlying theme. This site uses a lightweight preferences panel (shown in the Preferences tab) that works on top of whichever Jekyll theme is active.</p>

<p>This explains <strong>how the system applies user styling</strong>, how it interacts with themes, and how developers can safely extend it.</p>

<hr />

<h3 id="why-preferences-are-possible-across-themes"><strong>Why Preferences Are Possible Across Themes</strong></h3>

<p>Because theme switching (using <code class="language-plaintext highlighter-rouge">_themes/&lt;theme&gt;</code> and the Makefile) already ensures a consistent layout structure, we can apply an additional layer of styling that:</p>

<ol>
  <li>Does <strong>not modify the remote theme</strong></li>
  <li>Respects layout overrides like <code class="language-plaintext highlighter-rouge">opencs.html</code></li>
  <li>Works across <strong>Minima, TeXt, So Simple, Cayman</strong>, and future themes</li>
  <li>Is fully <strong>local to the user’s browser</strong> via <code class="language-plaintext highlighter-rouge">localStorage</code></li>
</ol>

<hr />

<h3 id="core-idea"><strong>Core Idea</strong></h3>

<p>We implement a set of <strong>CSS variables</strong> at the <code class="language-plaintext highlighter-rouge">:root</code> level (e.g.,<br />
<code class="language-plaintext highlighter-rouge">--pref-bg-color</code>, <code class="language-plaintext highlighter-rouge">--pref-text-color</code>, <code class="language-plaintext highlighter-rouge">--pref-font-size</code>).<br />
These variables override the site’s colors and typography at runtime.</p>
<div class="language-css highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="nd">:root</span> <span class="p">{</span>
  <span class="py">--pref-bg-color</span><span class="p">:</span> <span class="m">#0b1220</span><span class="p">;</span>
  <span class="py">--pref-text-color</span><span class="p">:</span> <span class="m">#e6eef8</span><span class="p">;</span>
  <span class="py">--pref-font-family</span><span class="p">:</span> <span class="n">Inter</span><span class="p">;</span>
  <span class="py">--pref-font-size</span><span class="p">:</span> <span class="m">14px</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div></div>

<p>When the user saves preferences, JavaScript updates the variables:</p>
<div class="language-javascript highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="nb">document</span><span class="p">.</span><span class="nx">documentElement</span><span class="p">.</span><span class="nx">style</span><span class="p">.</span><span class="nx">setProperty</span><span class="p">(</span><span class="dl">'</span><span class="s1">--pref-bg-color</span><span class="dl">'</span><span class="p">,</span> <span class="nx">prefs</span><span class="p">.</span><span class="nx">bg</span><span class="p">);</span>
</code></pre></div></div>

<hr />

<h3 id="why-user-theme-active-exists"><strong>Why <code class="language-plaintext highlighter-rouge">.user-theme-active</code> Exists</strong></h3>

<p>Every Jekyll theme ships with its own styles. To ensure user customizations override theme defaults, the site adds:</p>
<div class="language-html highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="nt">&lt;html</span> <span class="na">class=</span><span class="s">"user-theme-active"</span><span class="nt">&gt;</span>
</code></pre></div></div>

<p>Inside this class, we apply stronger rules:</p>
<div class="language-css highlighter-rouge"><div class="highlight"><pre class="highlight"><code><span class="nc">.user-theme-active</span> <span class="o">*</span> <span class="p">{</span>
  <span class="nl">color</span><span class="p">:</span> <span class="n">var</span><span class="p">(</span><span class="n">--text</span><span class="p">)</span> <span class="cp">!important</span><span class="p">;</span>
  <span class="nl">background-color</span><span class="p">:</span> <span class="n">var</span><span class="p">(</span><span class="n">--background</span><span class="p">)</span> <span class="cp">!important</span><span class="p">;</span>
<span class="p">}</span>
</code></pre></div></div>

<p>This guarantees user preferences override:</p>

<ul>
  <li>Minima’s palette</li>
  <li>TeXt’s typography</li>
  <li>So Simple’s white backgrounds</li>
  <li>Any custom <code class="language-plaintext highlighter-rouge">_sass</code> files</li>
</ul>

<hr />

<h3 id="how-background--panel-colors-are-computed"><strong>How Background + Panel Colors Are Computed</strong></h3>

<p>To ensure readability, the system automatically generates:</p>

<ul>
  <li>A panel color slightly offset from the background</li>
  <li>Input + button colors</li>
  <li>Borders, outlines, and shadows</li>
  <li>Text contrast for both dark and light modes</li>
</ul>

<p>These values use luminosity-based calculations so they remain readable regardless of the base background color.</p>

<hr />

<h3 id="why-this-approach-matters"><strong>Why This Approach Matters</strong></h3>

<ul>
  <li>Students control visual comfort without switching the entire theme</li>
  <li>Preferences apply per-user, not site-wide</li>
  <li>Overrides work consistently across all themes</li>
  <li>The system is lightweight and requires minimal maintenance</li>
</ul>

<p>This creates a layered system:</p>

<p><strong>Remote theme → Local layout overrides → User styling preferences</strong></p>

<p>Each layer is optional, isolated, and safe to change.</p>

<h3 id="summary">Summary</h3>

<ul>
  <li>Theme switching is managed via the Makefile and the _themes/ directory</li>
  <li>Layouts for posts and pages are overridden as needed, with a custom opencs.html as the local terminating layout.</li>
  <li>For most themes, layouts defer to the remote theme’s documentation. Remember: files are loaded locally first, then remotely. Overrides work for _layouts, _includes, and _sass. Try to minimize overrides to simply what is required for customizations.</li>
  <li>Most content uses post or page layouts for primary formatting. Exceptions include schedule.html, blogs.html, and search.html, which may use custom layouts.</li>
  <li>User styling preferences (font size, colors, width, etc.) are applied via CSS variables and localStorage, allowing per-user customization without modifying the active theme. The <code class="language-plaintext highlighter-rouge">.user-theme-active</code> class ensures user preferences override theme defaults across all supported themes.</li>
</ul>
